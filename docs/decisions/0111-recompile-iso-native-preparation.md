# ADR 0111: single-command ISO-to-native artifact preparation

- **Status:** Accepted.
- **Date:** 2026-11-09.
- **Context:** The project already has an ISO 9660 reader, SYSTEM.CNF BOOT2/BOOT resolution, create-new boot ELF extraction, a deterministic static ELF recompiler, initial EE RAM materialization, a parent-ISO provenance check, and a generated RG REPS2 ENGINE shared-module CMake project. Requiring developers to manually call extraction, remember the parent ISO, and separately configure the native recompiler increases operator error and risks losing provenance.
- **Decision:** Add `recompile-iso <disc.iso> <new-output-directory> [recompile options]` to orchestrate the existing stages. It resolves the input ISO to an absolute file, creates a new output directory only when it does not already exist, extracts the verified SYSTEM.CNF BOOT2 (preferred) or BOOT entry to `boot.elf`, and runs the existing compiler to emit `boot.cpp`/split parts, `boot.ram.bin`, `boot.manifest.json`, and `boot.native/`. Native-build output is mandatory for this command; parent-ISO provenance is automatic and cannot be overridden.
- **Provenance:** The exact original ISO SHA-256 and extracted boot ELF SHA-256 are recomputed/compared by the existing `validate_parent_iso` gate before the compiler publishes generated C++ and the native module project. The ISO is read-only and is never copied into the output directory.
- **Output safety:** Existing output directories are rejected without mutation. The command writes only into a newly created directory. If ISO extraction or any subsequent recompile stage fails, it removes the incomplete directory; if cleanup itself fails, both the original stage error and cleanup error are returned. It does not overwrite an existing user build.
- **Options:** Discovery, translation-unit count, probe budget, EE syscall HLE, relocated-code regions, and analysis-limit overrides reuse the existing `recompile-elf` option parser. `--parent-iso` is disallowed because the input ISO is already the explicit parent and `--native-build` is implied.
- **Validation:** A Rust CLI integration test builds a deterministic synthetic ISO containing SYSTEM.CNF and a valid MIPS ET_EXEC boot ELF. It checks the extracted bytes, 32 MiB RAM image, manifest and generated module project, source ISO immutability, exact ISO digest embedded in the generated CMake identity, refusal to reuse the output directory, and cleanup after invalid-ISO failure. Existing Windows/Linux CI continues to validate the generated module ABI and runner path separately.
- **Consequences:** The developer workflow now starts with the user-supplied ISO and does not require manual BOOT.ELF extraction or an externally supplied `--parent-iso` path. The result is still an experimental native artifact preparation project: CMake must build it, the runner must be invoked separately, and guest execution can stop at unresolved control flow, unsupported instructions, unimplemented system services or devices. This ADR does not claim a booted retail game, an end-user Play UI, or game compatibility.
