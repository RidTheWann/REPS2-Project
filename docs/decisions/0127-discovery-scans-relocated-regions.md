# ADR 0127: Function discovery also scans declared relocated-code regions

- **Status:** Accepted.
- **Date:** 2026-11-11.
- **Context:** ADR 0074 added `--relocated-code DEST:SOURCE:SIZE` regions as authoritative roots at their destination, but `discover_function_roots` gated scanning on the ELF section table's `SHF_EXECINSTR` ranges. Relocated destinations (e.g. Downhill's `0x80076000`) are not covered by any ELF section, so with a usable section table the discovery scan skipped the whole region: prologues and JAL targets inside the runtime-copied code were never candidates. The PostADR-0126 probe stopped as `unresolved_control_flow @ 0x80076440` — a function prologue (`addiu $sp,$sp,-16; sd $ra,...`) inside the declared region, reached only from copied code.
- **Evidence:**
  - **Observed (real-title probe, branch on `a642ef0`, Windows x64/MSVC):** before this change, the generated module had no `block_0x80076440` and the probe stopped `unresolved_control_flow @ 0x80076440` after 3,890,249 instructions. After extending the discovery executable ranges with each relocated region, the manifest reports `scanned_words` 364,352 → 365,020, `prologue_candidate_count` 3,763 → 3,769, accepted roots 7,155 → 7,169, blocks 60,484 → 60,585, and `block_0x80076440` is emitted. The probe now enters the copied code and stops deeper, at `unsupported_memory_access @ 0x800761A4` after 3,890,274 instructions (syscalls 149/131) — the next frontier.
- **Decision:** `discover_elf_with_discovery_and_relocated` appends every relocated region's destination range to the executable ranges passed to `discover_function_roots`, so the region is scanned for JAL targets, stack prologues, and data pointers exactly like a section-declared `.text`. This changes only discovery (candidate generation); reachability and ownership are unchanged.
- **Alternatives considered:**
  1. Treat relocated segments as executable via PF_X alone — rejected: when the section table is usable, section permissions deliberately override the coarse PF_X flag to keep data out of the code scan (ADR 0070); relocated regions are explicitly declared code by the caller, so extending the section-range list is the precise fix.
  2. Recursively analyze at runtime — rejected: static AOT requires all translated code to be known before execution.
- **Consequences:** Runtime-copied code regions are now fully discoverable; the M4 frontier moved from an unresolved relocated-region entry to a memory-access stop inside the copied code (`0x800761A4`), which the next unit should classify. Supersedes nothing; complements ADR 0074.
- **Validation:** New unit test `discovery_scans_relocated_regions_for_prologues_and_jal_targets` builds a synthetic ELF whose section table covers only the main segment; a JAL into a relocated region and a mid-region prologue (no direct branch) must both become translated blocks. `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace --locked` (341 lib tests), CMake Release build, `ctest -C Release` 40/40 on Windows x64/MSVC.
