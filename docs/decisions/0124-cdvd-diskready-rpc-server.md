# ADR 0124: Serve the CDVDFSV DiskReady RPC servers from host media presence

- **Status:** Accepted.
- **Date:** 2026-11-11.
- **Context:** After ADR 0123 restored runner/probe parity, the PostPR73 frontier was the delay spin at `0x00247AD0..0x00247AE4` ahead of `jal 0x0025CDB8` with `$a1 = 0x8000059C` — the `sceSifBindRpc` for the CDVDFSV **DiskReady** server. The title string `Libcdvd bind err CdDiskReady` is present in the image, and PS2SDK maps `0x8000059A` (`CD_SERVER_DISKREADY`, queue 1) and `0x8000059C` (queue 3, OSD path) both to `cbrpc_rpc2_diskready`.
- **Evidence:**
  - **Observed (PS2SDK `common/include/libcdvd-rpc.h`):** `cdvdfsv_rpc2_inpacket_t { int m_mode; }` (4 bytes) and `cdvdfsv_rpc2_outpacket_t { int m_retres; }` (4 bytes); `sceCdDiskReady(mode)` sends 4 bytes and returns `*(s32*)recv` (6 if the RPC itself fails).
  - **Observed (PS2SDK `iop/cdvd/cdvdfsv/src/cdvdfsv.c`):** `cbrpc_rpc2_diskready` answers `m_retres = sceCdDiskReady(inbuf->m_mode)`.
  - **Observed (PS2SDK `iop/cdvd/cdvdman/src/cdvdman.c` `sceCdDiskReady`):** queries the drive status register; a ready disc returns `SCECdComplete` (2), no disc returns `SCECdNotReady` (6); mode 8 returns the raw status byte whose ready pattern is `(x & 0xC0) == 0x40` (`cdvdman_devready`'s predicate). There is no `SCECdBusy` constant; busy is reported as 6.
  - **Observed (real-title probe, feature branch on `26db844`, Windows x64/MSVC 19.51.36260.0, Downhill Domination USA ISO SHA-256 `0fe2b777…a7eb86`):** with the server registered, the engine runner (`--budget 5000000 --max-batches 16 --hle-syscalls`) moved the frontier from `pc=0x00247AD0` (79,999,922 instructions, 168 syscalls seen / 151 handled) to `pc=0x002473A0` (79,999,924 instructions, 179 seen / 162 handled), trace confined to the `0x002473A0..0x002473B4` delay spin ahead of `jal 0x0025CDB8` with `$a1 = 0x80000595` — the **NCMD** server bind retry loop. So DiskReady's bind and call completed and execution advanced past it.
- **Decision:** Register both `0x8000059A` and `0x8000059C` in `initialize_hle_boot_environment`, served by `serve_ee_cdvd_diskready_call` for function 0 only. The handler requires the documented shape (4-byte readable request word, non-zero writable 4-byte reply), writes `m_retres` from host media presence — present: 2 for any mode except 8, and `0x40` for mode 8; absent: 6, and `0x00` for mode 8 — exactly the values a real drive returns, so this is not a fabricated success. Mode 0 would block the real IOP until ready; the HLE answers immediately and the deviation is documented. Any other function number or malformed shape returns false: no reply, no `SIF_CMD_RPC_END`, caller stays blocked (ADR 0114/0121 convention). New probe fields: `diskready_calls`, `diskready_replies`, `last_diskready_mode`, `last_diskready_retres`, `last_diskready_replied`.
- **Alternatives considered:**
  1. Answer 2 unconditionally — rejected: without host media the truthful answer is 6, and a fabricated ready would be a fake disc-presence claim.
  2. Block on mode 0 like the real IOP — rejected: the HLE layer has no interrupt scheduler; blocking would hang the bounded probe with no evidentiary gain.
  3. Model the raw register file — rejected: over-fitting to mode 8; the 0x40 ready pattern is the only documented consumer predicate.
- **Consequences:** The title's DiskReady bind/call now completes with a truthful media-derived answer, and the new frontier is the NCMD server (`0x80000595`) bind retry loop at `0x002473A0`, followed by SearchFile (`0x80000597`) — both need the ISO9660 path-table walker before any read answer can be truthful. Still a modelled-boundary advance, not a boot stage.
- **Validation:** Five new `reps2_hle_syscall_codegen_smoke` cases: both sids registered; media-present mode 0 → reply 2 with RPC_END + semaphore signal; mode 8 → `0x40`; no-media → 6; function 1 and an 8-byte send refused with no reply and no semaphore change. Full local chain passes on Windows x64/MSVC: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace --locked`, CMake Release build, `ctest -C Release` 40/40.
