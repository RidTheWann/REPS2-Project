# ADR 0114: SIFRPC server table, opaque server token and HLE call dispatch

- **Status:** Accepted. First server: CDVD CdInit (`0x80000592`).
- **Date:** 2026-11-10.
- **Context:** The observed title binds libcdvd's CdInit server (`0x80000592`) and retries until `cd->server` is non-NULL, then calls function 0 with a one-word request and a sixteen-byte reply. Answering every bind with the documented no-server reply is truthful but cannot advance a title past that loop, and inventing a successful bind alone would hand the guest a handle that leads nowhere. The runtime needs a real server table and a real call path, both bounded by evidence.
- **Evidence (PS2SDK, public sources):**
  - `ee/kernel/src/sifrpc.c` `sceSifBindRpc` clears `cd->server`, sends `SIF_CMD_RPC_BIND`, waits on a created semaphore and deletes it. `_request_end` writes `cd->server = request->sd`, `cd->buf = request->buf`, `cd->cbuf = request->cbuf` only for a bind, then signals `cd->hdr.sema_id` and frees the request. `sceSifCallRpc` writes `rpc_number`, `send_size`, `recvbuf`, `recv_size`, `rmode = 1` and `call->sd = cd->server` into `SifRpcCallPkt_t` and sends the request payload as the DMA entry preceding the command packet (`sceSifSendCmd`).
  - `common/include/sifrpc-common.h`: call packet fields at `+0x20` number, `+0x24` send size, `+0x28` reply buffer, `+0x2C` reply size, `+0x30` mode, `+0x34` server token; client `server` at `+0x24` and `end_function` at `+0x1C`.
  - `ee/kernel/src/sifcmd.c` `sceSifSendCmd` appends the command packet last with `SIF_DMA_ERT | SIF_DMA_INT_O`, so the preceding entry is the extra payload.
  - `ee/rpc/cdvd/src/libcdvd.c`: `CD_SERVER_INIT` is `0x80000592`; `sceCdInit` calls function 0 with a four-byte mode and a sixteen-byte reply (`CdInitPkt`), then returns 1.
  - Disassembly of the owner-supplied boot ELF (local evidence, recorded in `docs/RESEARCH.md`): all eighteen bind sites only zero-test `cd->server`; `sceSifCallRpc` copies it into the call packet at `+0x34`, and no guest code dereferences it.
- **Decision:** Model the IOP SIFRPC server table as a bounded array of `{sid, queue, handler}` entries, searched with `_search_svdata` ordering (lowest queue first, registration order within a queue). Only servers the runtime actually implements are registered; `initialize_hle_boot_environment` installs them. A registered server's bind reply carries its **sid as an opaque `sd` token**, because the EE only zero-tests and forwards that value and REPS2 has no IOP address to name. `buf` and `cbuf` stay zero: they name IOP-side server buffers that are not modelled and that the EE only uses as SIF DMA destinations.
- **Call dispatch:** On `SIF_CMD_RPC_CALL`, decode the call packet and the preceding payload entry, look the token up, and invoke the handler. The handler writes its reply payload directly into the caller's EE reply buffer, because there is no IOP memory to DMA from. A successful handler plus `rmode != 0` produces a `SIF_CMD_RPC_END` reply naming `cid = SIF_CMD_RPC_CALL`, which the existing EE-side `_request_end` model uses to raise the caller's semaphore and free the request packet. An unregistered token, an unsupported function number, an absent payload, or `rmode == 0` produces **no reply**: the caller stays blocked, matching a real IOP callback that returns NULL. No error status is invented.
- **First server:** CdInit (`0x80000592`, function 0). Reply `{retres = 1, cdvdfsv_ver = 0, cdvdman_ver = 0, debug_mode = 0}`. `retres = 1` states that the HLE CDVD driver accepted initialization; it does not claim a disc is present. The version words are zero, which the SDK itself uses for "not reported", because REPS2 has no CDVDFSV/CDVDMAN build to name.
- **Alternatives considered:**
  1. Answer every bind with a synthetic success and no server — rejected: the guest would call into a token that resolves to nothing, and the success would be fabricated.
  2. Return a synthetic IOP address as `sd` — rejected: it invents an IOP memory layout and is no more informative than the sid the guest already knows.
  3. Implement the whole CDVD library before any dispatch path — rejected: the registry, call path and failure rules are independently testable and are the prerequisite for every later server.
- **Consequences:** A title can now bind a server REPS2 implements, call it, receive a reply and continue. Binding any other sid still yields the documented no-server reply. Guest `end_function` callbacks, IOP backpressure, SIF1 traffic and CDVD DiskReady/SearchFile/read remain unmodelled and are not claimed. An `end_function` pointer is recorded but not entered.
- **Validation:** `reps2_hle_syscall_codegen_smoke` adds registry bound/duplicate/queue-order cases, a bind that returns the token, a call that reaches the server and releases the wait, an unregistered-token call that writes nothing, a refused function number that replies nothing, and the boot environment's CdInit server writing `{1,0,0,0}`. `rg_reps2_engine_smoke` covers the session media ordering.
