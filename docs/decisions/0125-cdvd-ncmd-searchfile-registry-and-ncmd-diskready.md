# ADR 0125: Register the NCmd/SearchFile servers and serve NCmdDiskReady

- **Status:** Accepted.
- **Date:** 2026-11-11.
- **Context:** After ADR 0124 (DiskReady servers answered from host media presence), the Downhill Domination probe moved from the `0x00247AD0` DiskReady-bind spin to the NCMD bind retry spin at `0x002473A0` (bind sid `0x80000595`). Registering the NCMD and SearchFile servers with fail-closed handlers let the real-title probe name the first call: the engine-runner report showed `ncmd_calls=1, ncmd_number=14` with `rpc_call_replied=0`, then `semaphore_wait_blocked` at `pc=0x0025A724` after 3,889,518 instructions — function 14 is `CD_NCMD_DISKREADY`.
- **Evidence:**
  - **Observed (PS2SDK `ee/rpc/cdvd/src/ncmd.c`):** `sceCdNCmdDiskReady` calls `sceSifCallRpc(&clientNCmd, CD_NCMD_DISKREADY /*14*/, 0, NULL, 0, &nCmdRecvBuff, 4, ...)` — empty request, 4-byte `m_retres`; 2 = SCECdComplete, 6 = SCECdNotReady. Server side `cbrpc_rpc5_cdvdncmds` case 14 answers from the drive: 2 when ready, 6 when not.
  - **Observed (real-title probe, feature branch on `7edee57`, Windows x64/MSVC, Downhill USA):** with both servers registered but refusing, `sif` report = `diskready_calls=1 diskready_retres=2` (media present), `ncmd_calls=1 ncmd_number=14 rpc_call_replied=0`, stop `semaphore_wait_blocked @ 0x0025A724`, executed=3,889,518. After implementing fno 14: `ncmd_replies=1 ncmd_retres=2 ncmd_replied=1`, and the run advances to a new stop at `pc=0x0025C774`, executed=3,889,750, syscalls 146 seen / 129 handled.
  - **Observed (decoded words around the new stop):** `0x0025C770 beq $10,$0 -> 0x0025C7C4` with delay slot `0x0025C774`, and `0x0025C7BC bgtz $10 -> 0x0025C774` — a backward branch whose target is another instruction's delay slot. The guest stopped `unresolved_control_flow` there because the analyzer currently rejects delay-slot-entry targets (ARCHITECTURE.md), although on hardware the target instruction executes as an ordinary instruction. That is the next unit.
- **Decision:** Register `kEeSifServerCdNCmd` (`0x80000595`) and `kEeSifServerCdSearchFile` (`0x80000597`) in `initialize_hle_boot_environment`. The NCMD handler serves function 14 only, requiring the documented shape (send_size 0, writable 4-byte reply), answering 2 with host media present and 6 without, writing `m_retres` and returning true so RPC_END is sent and the caller's semaphore is signalled. All other NCMD functions and all SearchFile calls are recorded (`ncmd_call_count`/`last_ncmd_number`, `searchfile_call_count`/`last_searchfile_number`, plus new `ncmd_replies`/`last_ncmd_retres`/`last_ncmd_replied`) and refused with no reply. The engine runner JSON report and the generated probe line now carry these `sif` fields. SearchFile stays fully fail-closed until an ISO9660 path-table walker exists, because its reply DMA-writes file metadata into EE memory.
- **Alternatives considered:**
  1. Leave NCMD unregistered — rejected: the bind gets the no-server reply and the title spins in the retry loop without ever naming a function (ADR 0104 behavior).
  2. Answer NCMD 14 unconditionally — rejected: without media the truthful answer is 6.
  3. Implement all NCMD functions — rejected: no evidence yet for which functions the title issues beyond 14; each gets modelled from its own observed call.
- **Consequences:** The title's first NCMD call now completes with a truthful media-derived answer. Next frontier is the `unresolved_control_flow` at `0x0025C774` (delay-slot-entry branch target), a CFG correctness gap, then SearchFile (`0x80000597`) which needs the ISO9660 walker. Still modelled-boundary, not a boot stage.
- **Validation:** New smoke cases: both servers registered; NCMD 14 with media → reply 2 + RPC_END + semaphore signal; without media → 6; non-empty request refused; unmodelled NCMD/SearchFile calls recorded and refused with no reply and no semaphore change. Local chain on Windows x64/MSVC: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace --locked`, CMake Release build, `ctest -C Release` 40/40 (one JSON-formatting defect in the runner report found by `reps2_native_build_driver_smoke` was fixed: the `sif` object needed the extra closing brace for `session`).
