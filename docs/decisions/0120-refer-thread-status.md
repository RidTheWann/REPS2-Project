# ADR 0120: `ReferThreadStatus` and the thread status block

- **Status:** Accepted.
- **Date:** 2026-11-10.
- **Context:** With the `PollSema` success value corrected (ADR 0119) the PostPR70 real-title probe leaves the poll loop (`poll_sema=1 poll_sema_acquired=1`) and stops as `unhandled_syscall` service `0x30` at `0x0025A5E4` after 3,172,922 instructions, with `$a0 = 1` and `$a1 = 0x007607D8`. The layer models the thread record for CreateThread/StartThread/GetThreadId/ChangeThreadPriority but had no service that reports a thread's status block.
- **Evidence:**
  - **Observed (PS2SDK `ee/kernel/include/kernel.h`):** `extern s32 ReferThreadStatus(s32 thread_id, ee_thread_status_t *info);` and `extern s32 iReferThreadStatus(...)`. `TH_SELF 0` is documented as "the calling thread" and noted as supported specifically by `ReferThreadStatus()` and `ChangeThreadPriority()`. `THS_RUN 0x01`, `THS_READY 0x02`, `THS_WAIT 0x04`, `THS_SUSPEND 0x08`, `THS_WAITSUSPEND 0x0C`, `THS_DORMANT 0x10`; `TSW_NONE 0`, `TSW_SLEEP 1`, `TSW_SEMA 2`. `ee_thread_status_t` is twelve 32-bit words (`sizeof == 0x30`): status, func, stack, stack_size, gp_reg, initial_priority, current_priority, attr, option, waitType, waitId, wakeupCount.
  - **Observed (boot ELF, local evidence):** the thunk at `0x0025A5E0`..`0x0025A5EC` is `li $v1,0x30; syscall; jr $ra; nop`. It has three call sites — `0x00247010`, `0x0024734C`, `0x00247664` — and every one loads the thread id from `0x007607D0` into `$a0` and builds `$a1 = 0x007607D8` in the call delay slot. No instruction in this image ever loads from the 0x007607D8..0x00760808 block: the buffer is write-only here, and the three callers ignore `$v0`.
  - **Observed (boot ELF crt0, local evidence):** at `0x0010A148`..`0x0010A178` the words set `$a0 = 0x002A40F0` (gp), `$a1 = 0x0093CAE0` (stack), `$a2 = 0` (stack_size), `$a3 = 0x0029E580` (args) and `$8 = 0x0010A1D0` before `li $v1,0x3C; syscall`. `0x0010A1D0` decodes as `li $v1,0x23; syscall` — the `ExitThread` thunk — so the fifth argument is the boot thread's root function and the EE syscall ABI carries it in `$8`.
  - **Observed (real-title probe, PostPR70 local evidence):** `unhandled_syscall` `0x30` at `0x0025A5E4` with `$a0 = 1` (the GetThreadId result stored by the caller) and `$a1 = 0x007607D8`, after 3,172,922 instructions and one successful `PollSema` acquisition.
  - **Unknown:** the kernel TCB contents for the boot thread beyond the SetupThread inputs (attr/option are not observed), and whether ps2tek documents a specific success value; the observed callers ignore `$v0`.
- **Decision:** Model `ReferThreadStatus` (0x30, plus the `iReferThreadStatus` magnitude alias) as a documented status-block writer:
  1. Accept `TH_SELF` (0) and the boot thread id 1 as the executing thread; accept a live created record id; refuse every other id with the documented failure `-1` and write nothing.
  2. Validate the full 48-byte, 4-byte-aligned destination in EE main RAM before the first store, so a refusal cannot partially write the guest block.
  3. The boot thread reports `THS_RUN`, the SetupThread-recorded gp, the stack region (`stack_top - stack_size`, `stack_size`), the recorded root function from `$8`, the ps2tek-documented boot priority 0 as initial priority, and the recorded current priority. `attr`/`option` stay zero because no source records them, and `waitType`/`waitId`/`wakeupCount` are `TSW_NONE`/0/0 because the runtime has no wait or wakeup history.
  4. A created record reports the CreateThread fields, the DORMANT/READY status its services assigned, and the same zero wait fields. No scheduler state is invented.
  5. Success returns 0. The observation counters record the requested id, the status word written, and the refusal reason.
- **Alternatives considered:**
  1. Fail closed on the boot-thread record until the kernel TCB is observable — rejected: the documented contract plus the observed SetupThread inputs and root function are sufficient to report the executing thread's block without inventing wait state; refusing would stop the title at a documented service with recoverable evidence.
  2. Report `attr`/`option` from the ELF header or crt0 constants — rejected: no evidence ties either value to the kernel's thread record.
  3. Report created threads only — rejected: the observed call asks for the boot thread (`$a0 = 1`).
- **Consequences:** the run can continue past `0x0025A5E4`. The block is a faithful rendering of the host thread record; it is not a claim that REPS2 models EE kernel TCB layout or a scheduler. Guest code that polls a created thread sees DORMANT/READY, never RUN, because no dispatcher switches contexts yet.
- **Validation:** `reps2_hle_syscall_codegen_smoke` adds three cases: the boot thread reports THS_RUN with the SetupThread/root-function/priority fields and both the explicit id and TH_SELF succeed; a created thread reports DORMANT then READY with its CreateThread fields, including the 0x30 dispatch path resuming at the return PC; and an invalid id plus an unwritable buffer each return -1 without modifying the prefilled 48-byte block. The real-title probe that motivated this ADR recorded the pre-fix `unhandled_syscall` state.
