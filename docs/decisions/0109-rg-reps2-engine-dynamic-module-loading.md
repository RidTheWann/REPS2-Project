# ADR 0109: RG REPS2 ENGINE dynamic-module ABI, loading and lifetime

- **Status:** Accepted.
- **Date:** 2026-11-09.
- **Context:** The initial engine session implementation admitted only linked functions and left module code/name lifetime to the caller. The next execution-layer requirement is to load separately compiled native artifacts without weakening the guest runtime ABI, adding per-instruction dispatch overhead, or allowing a session to call into an unloaded library.
- **Decision:** Use a versioned POD descriptor returned by one exported C-linkage symbol. The descriptor carries a size/version header, fixed-width metadata, a toolchain/runtime-layout fingerprint, the host target, and initializer/execute callbacks with C ABI signatures. Guest state crosses the callback boundary only as an opaque pointer; the module must compile against the exact matching REPS2 runtime headers and ABI.
- **Compatibility:** Engine ABI is raised to 2. Descriptor ABI starts at 1. The engine rejects unknown descriptor sizes/versions, nonzero reserved fields, invalid names, mismatched engine/runtime versions, mismatched toolchain fingerprints, unsupported targets, missing callbacks, and out-of-range runtime status values. The toolchain fingerprint combines compiler and standard-library identifiers, relevant ABI/configuration macros, pointer width, and shared-state sizes/alignments. It is not a cryptographic identity or a substitute for incrementing the runtime ABI when contracts change.
- **Loading:** Resolve the requested path to a canonical absolute regular file before loading. On Windows, use `LoadLibraryExW` with restricted search flags so the DLL's own directory is available for its dependencies without broad current-directory/PATH lookup. On ELF-family targets, use `dlopen(RTLD_NOW | RTLD_LOCAL)`; resolve only the documented descriptor symbol with `dlsym`. Android uses the NDK's `libdl` support and must explicitly link the loader library.
- **Lifetime:** Do not call `FreeLibrary` or `dlclose` in this increment. Loaded module code is pinned until process exit. `PreparedNativeModule` copies its display name and retains a shared library reference; `EngineSession` retains its own copy, so caller-handle destruction cannot invalidate a live session. Dynamic unload is not supported.
- **Security:** A loaded native module executes with the application's process privileges. The loader is not a sandbox and does not authenticate signatures or publisher identity. It is only for trusted modules; package hashing/signing and trust policy are separate work.
- **Performance:** Callbacks are invoked only at session initialization and at each budgeted run request. Basic-block and instruction dispatch stay in generated native code. No interpreter or per-instruction host callback is introduced.
- **Frontend integration:** `--native-build` now emits `rg_reps2_module.cpp` beside the existing probe and translation units. The generated CMake project builds the exact same dispatcher/part sources as a shared library, with the exported descriptor getter and callbacks adapting `initialize_ee_state` and `execute_cfg`. It emits a configuration-specific path file containing the actual platform artifact location; it does not embed absolute include paths into source or manifests.
- **Validation:** CI separately tests the small platform loader fixture (including missing symbol/path, transactional output preservation, and prepared-handle/session lifetime) and then builds the frontend-generated CFG module, loads that exact DLL/SO through the engine loader, starts an EngineSession, releases the caller's prepared handle, and executes guest instructions. This end-to-end generated-artifact path must pass on Windows/MSVC and Linux/GCC. It remains a synthetic fixture, not proof that an actual PS2 title boots.
- **Deferred:** signed module manifests and publisher trust policy, secure content-addressed cache, explicit unload/quiescence, requested-target code generation, AArch64 machine-code backend, Android/macOS CI validation and platform integration.
