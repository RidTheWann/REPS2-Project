# ADR 0123: EngineSession establishes the modelled HLE boot environment

- **Status:** Accepted.
- **Date:** 2026-11-11.
- **Context:** The generated `--hle-syscalls` probe seeds the modelled device state by calling `reps2::runtime::initialize_hle_boot_environment(state)` after the generated initializer (rust/frontend/src/native_build.rs). `EngineSession::start` only set `state_.hle.syscall_enabled = config.enable_ee_syscall_hle` (engine/include/rg_reps2_engine/session.hpp); it never established the boot environment, so the DMAC `D_STAT` state stayed unknown when a module ran through `rg-reps2-engine --hle-syscalls`.
- **Evidence:**
  - **Observed (real-title probe, exact `origin/main` `2cb1fd2545ed21218ed2d4a2aedfe3db82181725`, Windows x64/MSVC 19.51.36260.0):** Downhill Domination USA (ISO SHA-256 `0fe2b77713d3440cc3030741ea0b18f49e3feaa09671a30a421e0d4888a7eb86`, boot ELF SHA-256 `adfda7b73a8f05fb20a3f0f318772e9d3797fd4d6c0a6c0078ae392df0f0cf0c`) run through `rg-reps2-engine --hle-syscalls --budget 5000000 --max-batches 16` stopped as `unsupported_memory_access` at `pc=0x0025C274` after 3,168,708 instructions. The instruction at `0x0025C274` is `lw $3, 0($2)` with `$2 = 0x1000E010` (`lui $2,0x1000; ori $2,$2,0xE010` at `0x0025C26C/0x0025C270`), i.e. a `D_STAT` read that fails closed while `d_stat_known == false` (runtime/include/reps2/runtime/ee_state.hpp `mmio_read_d_stat`).
  - **Observed (same module through the generated probe):** `reps2_probe.exe boot.ram.bin 5000000` reproduced the documented PostPR73 result exactly: `stage=budget_exhausted, pc=0x00247AD0, executed=4,999,997`.
  - **Derived:** the probe and the engine runner diverged only in boot-environment seeding; the engine path was missing the seed.
- **Decision:** When `SessionConfig::enable_ee_syscall_hle` is true, `EngineSession::start` calls `initialize_hle_boot_environment(state_)` after the module initializer runs and before the session becomes ready, exactly matching the generated probe. Without the option, no modelled device state is seeded (fail-closed default is unchanged).
- **Alternatives considered:**
  1. Seed the boot environment unconditionally — rejected: it would change the default (non-HLE) session contract and could make unsupported device reads appear known without the opt-in.
  2. Seed it inside the generated module initializer — rejected: the initializer must stay a pure ELF-image loader; the HLE layer is a host/session option.
- **Consequences:** `rg-reps2-engine --hle-syscalls` now reproduces the generated-probe frontier on the real title. **Observed after the fix (same exact-main module, `--budget 5000000 --max-batches 16`):** `outcome=budget_limit_reached`, `pc=0x00247AD0`, `executed=79,999,922` over 16 batches, instruction trace confined to the `0x00247AD0..0x00247AE4` delay loop (`addiu $2,$2,-1; bne $2,$3,-1` retry spin ahead of the `sceSifBindRpc` call for sid `0x8000059C`, the CDVDFSV DiskReady server). The next frontier remains the unserved DiskReady/SearchFile RPC servers, not an instruction gap. Black (USA) (ISO SHA-256 `65768cade88bfbaf566b67a3ef7a0bda5a9669779833914ffe7cd73a3e45cccd`) on the same revision stops as `guest_stopped` at `pc=0x80076000` after 479,362 instructions — unresolved control flow into runtime-copied code, because Black declares no `--relocated-code` regions; this matches its historical pre-relocated-region behavior and is not a regression.
- **Validation:** `tests/rg_reps2_engine_smoke.cpp` now asserts that a session started with `enable_ee_syscall_hle=true` has `dmac.d_stat_known == true`, and that a session without the option leaves both `hle.syscall_enabled` false and `d_stat_known` false. `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace --locked`, CMake Release build and `ctest -C Release` (40/40) pass on Windows x64/MSVC. This fixes runner/probe parity; it is not a guest-visible boot stage.
