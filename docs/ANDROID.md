# Android arm64-v8a — deferred

## Historical exploratory evidence

Android implementation is deferred while Windows x64 desktop delivery is the active target. The NDK cross-build was an engineering experiment only and is no longer a maintained CI gate.

## What the earlier cross-build verified

The Android CI job builds two native outputs with the Android NDK:

1. The standalone `rg-reps2-engine` executable, which links the project engine loader/session implementation.
2. A synthetic AOT shared module generated by the host-built Rust frontend and compiled by the Android toolchain.

The build pins Android NDK r30 (`30.0.16248370`), `ANDROID_ABI=arm64-v8a`, `ANDROID_PLATFORM=android-24`, and `ANDROID_STL=c++_shared`. A small compile-time probe asserts that the compiler sees both `Architecture::arm64` and `OperatingSystem::android`. LLVM `readelf` verifies the runner and module are AArch64 ELF, the module exports `rg_reps2_get_native_module_descriptor_v1`, and both link against `libc++_shared.so`.

The workflow uploads the cross-compiled runner, synthetic module, shared C++ runtime and ELF/symbol reports as `rg-reps2-engine-android-arm64-v8a`.

**This is not Android runtime support.** GitHub's x86-64 Linux runner cannot execute these ARM64 Android binaries. No Android device/emulator load test, Gradle/APK packaging, JNI bridge, application lifecycle, storage permission flow, Vulkan/GPU, audio/input subsystem, game boot or gameplay is established. API 24 is a reproducible CI compilation target, not a product minimum-SDK decision.

## Reproduce the engine runner build

With Android SDK command-line tools and NDK r30 installed:

```bash
NDK="$ANDROID_SDK_ROOT/ndk/30.0.16248370"

cmake -S . -B build/android-arm64/engine \
  -DCMAKE_TOOLCHAIN_FILE="$NDK/build/cmake/android.toolchain.cmake" \
  -DANDROID_ABI=arm64-v8a \
  -DANDROID_PLATFORM=android-24 \
  -DANDROID_STL=c++_shared \
  -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_TESTING=OFF

cmake --build build/android-arm64/engine \
  --target rg_reps2_engine_runner --config Release --parallel
```

The project is configured with the Android toolchain, and only the runner target is built. The Rust frontend remains a host tool; this command does not try to execute ARM64 test binaries on the development host.

## Reproduce a generated module build

Build the Rust frontend on the host and use it to generate a synthetic native module project:

```bash
cargo build --locked --release --manifest-path rust/Cargo.toml
build/target/release/reps2 compile-cfg-fixture build/android-arm64/synthetic.cpp \
  --native-build --probe-budget 64
```

Configure and build the generated shared module with the same NDK target settings:

```bash
cmake -S build/android-arm64/synthetic.native \
  -B build/android-arm64/synthetic-native \
  -DCMAKE_TOOLCHAIN_FILE="$NDK/build/cmake/android.toolchain.cmake" \
  -DANDROID_ABI=arm64-v8a \
  -DANDROID_PLATFORM=android-24 \
  -DANDROID_STL=c++_shared \
  -DCMAKE_BUILD_TYPE=Release \
  -DREPS2_RUNTIME_INCLUDE="$PWD/runtime/include" \
  -DREPS2_ENGINE_INCLUDE="$PWD/engine/include"

cmake --build build/android-arm64/synthetic-native \
  --target reps2_native_module --config Release --parallel
```

The generated `.so` is a synthetic test module, not a PS2 game module proven to boot on Android. A consuming Android application must package the matching `libc++_shared.so` alongside its native libraries when using the shared STL. Load only trusted modules: dynamic native code runs with the host process's privileges and is not sandboxed.

## Remaining Android gates

- Run the loader and a synthetic EngineSession on an ARM64 Android device or emulator.
- Validate dynamic-loader behavior, filesystem paths, shared C++ runtime packaging and process lifecycle in an Android application.
- Establish an app/JNI boundary, Gradle packaging and device-specific logging/crash reporting.
- Integrate Android input, display/GPU, audio and storage policy behind explicit platform interfaces.
- Run bounded title probes on device, then record title-specific results. Cross-compilation must never be promoted to a boot/playability claim.
