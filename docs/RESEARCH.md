# Research references and provenance policy

This file records public materials that can guide independent implementation. It is not a claim that every behavior has already been verified. Record the exact document revision, page/section, test vector, and observed result when a reference is used to implement behavior.

## Primary technical references

- Sony PlayStation 2 hardware manuals collected by the PS2Docs community: https://github.com/4kbyter/ps2docs and https://github.com/ninjadynamics/PS2Docs. These repositories index EE, GS, VU, and SPU2 documentation. Verify the provenance and revision of each document before relying on it.
- PS2 ELF and toolchain research should be cross-checked against independent homebrew/toolchain documentation and real ELF metadata; do not assume generic MIPS ELF conventions cover every PS2-specific variant.
- The MIPS ELF ABI specification documents standard MIPS relocation types and formulas: https://refspecs.linuxfoundation.org/elf/mipsabi.pdf.

## Public projects for architectural study only

- PS2 Web Recomp: https://github.com/snuri00/ps2-web-recomp. Useful for studying the division between EE AOT translation, code exploration, runtime support, vector-program compilation, and graphics execution.
- PS2Recomp: https://github.com/ran-j/PS2Recomp. Useful for studying an experimental ELF/Ghidra/configuration/C++ generation workflow and its documented limitations.
- PCSX2: https://github.com/PCSX2/pcsx2. May be used as an external behavioral reference and differential-test target. REPS2 must not copy or adapt PCSX2 implementation code.

These projects have different goals and levels of completeness. Their demos and feature lists are not proof that REPS2 has equivalent capabilities.

## Provenance rules

1. REPS2 source is independently authored and must not be copied from emulators, recompilers, decompilers, leaked SDKs, or game binaries.
2. Public manuals and specifications may be cited as technical references. Keep a source note next to non-obvious semantics.
3. External test oracles may be queried for behavior, but only observable inputs/outputs and independently written tests are recorded.
4. Do not add game ISOs, BIOS images, proprietary headers/libraries, assets, or extracted code to this repository.
5. Synthetic fixtures must be generated by tests or checked in only when entirely authored by REPS2 contributors.
6. When two references disagree, record both, create a minimal test, and avoid silently picking the convenient behavior.

## Initial design decisions

- Host target: Windows x64 first, with Linux CI to catch portability assumptions.
- Implementation language: C++20, dependency-free in the initial core, to keep MSVC support straightforward.
- Initial file-format scope: ELF32 little-endian metadata parsing. PS2-specific variants and extended ELF numbering require explicit tests before support is claimed.
- Initial instruction scope: a subset of base MIPS integer instructions; it is not the complete R5900 ISA.
- Runtime strategy: modular services with game-driven implementation priorities; no requirement to finish all hardware research before a working compiler pipeline exists.
