# REPS2 capabilities (v0.7.0)

Detailed status and capability list, moved out of the README. The roadmap in [ROADMAP.md](ROADMAP.md) records what is still open.

## Status

> **Status: experimental AOT foundation (v0.7.0).** REPS2 now has a bounded read-only ISO 9660 reader for raw 2048-byte-sector images with SYSTEM.CNF BOOT2/BOOT executable discovery, a bounded ELF32 little-endian parser, initial symbols and REL/RELA metadata, a deliberately partial R5900 decoder with a deterministic executable-byte coverage profiler that counts complete naturally aligned words within each file-backed executable segment (excluding partial words and BSS) and a bounded entry-point scan, a typed scalar IR with MMI0 modulo-lane operations (PADDW/PSUBW/PADDH/PSUBH), the lane-saturating PADDUW operation, the MMI2 low-doubleword copy PCPYLD, the MMI3 128-bit bitwise OR POR, and the MMI0 interleaves PEXTLW and PEXTLB (low word and low byte), the word pack/copy PPACW and PCPYUD, the single-source permutations PEXEW and PROT3W, the saturating PADDUB, and the 128-bit bitwise PAND, PXOR and PNOR, the EE single-precision FPU's data-movement set (MFC1/MTC1/CFC1/CTC1/LWC1/SWC1), its S/W-class arithmetic on an integer-only, non-IEEE numeric model with the separate ACC register and FCR31 flag routing, and the four COP1 compare predicates with the BC1F/BC1T/BC1FL/BC1TL branch family driven by FCR31's condition bit, VU0 LQC2/SQC2 quadword data movement with constant VF0 and a distinct VF register file (ADR 0078), a reachability-guided CFG, a CFG-aware control IR, deterministic C++20 lowering for a documented scalar/control-flow subset, byte/halfword/word/doubleword/quadword EE main-RAM loads and stores, including the R5900 left/right partial word and doubleword merge family, plus PT_LOAD-to-main-RAM image construction and a generated ELF-entry initializer. Generated control-flow C++ now emits one function per basic block with sorted-table dispatch and can be split across a dispatcher plus multiple translation units, and a guest `syscall` is offered to an opt-in EE kernel HLE layer (`SetupThread`, `SetupHeap`, `CreateThread`, `StartThread`, `GetThreadId`, `ChangeThreadPriority`, `CreateSema`, `FlushCache`) that resumes serviced calls and reports unimplemented services instead of faking them. CMake builds synthetic scalar, R5900 HI/LO/multiply, control-flow, memory and initialization programs, compiles the generated C++, and executes them in CI on Windows and Linux. The ELF-to-C++ command now emits a C++ translation, a companion 32 MiB initial RAM image, and a deterministic machine-readable build manifest for eligible static ELFs; full R5900 coverage, relocations, TLB mapping, asynchronous interrupts and exception types beyond the implemented SYSCALL/BREAK/OVERFLOW/conditional Trap, instruction-fetch AdEL, and checked data-alignment AdEL/AdES Level-1 paths, a fail-closed EE INTC register file (`I_STAT`/`I_MASK`, ADR 0103) that delivers no interrupt, a read-only host media boundary (`HostMediaSource`, ADR 0106) that the standalone RG REPS2 ENGINE runner can now connect to a raw ISO sector source, EE DMAC registers named as in the SDK (`D_CTRL`/`D_STAT`/`D_PCR`) with the documented DMAC interrupt condition modelled as a pure predicate that delivers no exception (ADR 0105), a generated native shared-module wrapper/build target and bounded host runner, MMIO device coverage, system services beyond that EE syscall layer, real-title boot evidence, and game compatibility are not complete.
- Decode and lower MMI0 PEXT5/PPAC5 as single-source 1-5-5-5 to 8-8-8-8 conversions across four 32-bit lanes; PPAC5 truncates packed output rather than rounding or saturating.

## Current capabilities

- Add one owned PS2 ISO directly to a managed multi-game library with `reps2 add-game`; identify the disc by streaming SHA-256, resolve SYSTEM.CNF BOOT2/BOOT, extract and validate the boot ELF internally, and write a versioned per-game JSON manifest plus any currently available analysis/code-generation artifacts. The original ISO remains at its source path and is not copied. Imported records are explicitly marked non-playable until the native PS2 runtime and title-stage validation exist.

- Inspect raw 2048-byte-sector ISO 9660 images without loading the entire disc; validate the descriptor sequence and single-volume PVD, list root entries, resolve nested paths, and parse SYSTEM.CNF with BOOT2 preferred over BOOT.
- Extract the SYSTEM.CNF boot target only after validating it as a MIPS ET_EXEC ELF; use create-new output semantics so an existing file or source image is never overwritten.
- Provide `recompile-iso` as a single bounded preparation command: resolve BOOT2/BOOT, validate and extract the static boot ELF, generate its initial RAM image/manifest/C++ units and RG REPS2 ENGINE native-module project, bind the exact boot ELF to the source ISO SHA-256, and refuse an existing output directory. Failed preparations clean their incomplete output; the source ISO remains unchanged. This is artifact preparation, not title boot evidence.
- Parse ELF32 little-endian headers, program headers, section headers and section names, symbol tables, and REL/RELA entries.
- Validate file-backed ranges, table bounds, leading/trailing null bytes in non-empty string tables, the required SHT_NULL section zero, symbol-table local/global partitioning, regular symbol section indices, relocation symbol/target links, entry sizes, address overflow, and parser resource limits. Accept a zero-size SHT_SYMTAB/SHT_DYNSYM with sh_info zero as a legal empty table, as emitted by stripped retail linkers.
- Decode MIPS e_flags diagnostically: report the CPU subtype, ABI and ISA-level fields, recognized feature bits and any unclassified bits. The R5900 CPU marker is exposed without treating a header flag alone as proof of title compatibility.
- Parse MIPS .reginfo sections and PT_MIPS_REGINFO segments into GPR/coprocessor usage masks and the signed $gp value; enforce PT_MIPS_REGINFO uniqueness, 24-byte payload size and placement before PT_LOAD when present. Decode PT_MIPS_ABIFLAGS program-header payloads and version-zero .MIPS.abiflags section payloads with one shared decoder, recognize the R5900 ISA extension code, and preserve unknown versions and flag masks.
- Parse bounded .MIPS.options descriptor streams, decode the 24-byte ELF32_RegInfo payload of ODK_REGINFO, and retain raw kind, size, affected-section index, info word and opaque-payload length for other or unknown descriptor kinds. This is diagnostic metadata, not ABI admission policy.
- Preserve EI_OSABI and EI_ABIVERSION; report the generic OS ABI registry label and raw ABI-version byte, and classify standard ELF object types plus OS-specific/processor-specific e_type ranges while retaining unknown codes.
- Preserve ELF special symbol section indices such as SHN_ABS/SHN_COMMON and resolve SHN_XINDEX through a validated SHT_SYMTAB_SHNDX table. Resolve e_shnum/e_shstrndx and PN_XNUM extended values through section-header zero, with configurable section and program-header count limits.
- Materialize PT_LOAD segments with zero-filled memory-only tails; reject overlapping guest virtual ranges, including overlaps introduced by same-base pure-BSS coalescing regardless of program-header order.
- Decode an explicitly scoped base-MIPS integer subset, including BEQ/BNE/BLEZ/BGTZ and REGIMM BLTZ/BGEZ branch families.
- Expose conservative per-instruction GPR/HI-LO dependencies, memory/control-flow effects, and possible synchronous exceptions; unsupported encodings remain explicitly opaque.
- Decode, lift and AOT-lower base EE MTHI/MTLO/MFHI/MFLO plus R5900 three-operand MULT/MULTU; preserve HI/LO, the optional GPR destination, and both EE GPR lanes.
- Decode, lift and AOT-lower 64-bit NOR, signed/unsigned SLT/SLTU, and SLTI/SLTIU with signed immediate extension and low-lane-only result writes.
- Decode, lift and AOT-lower trapping 64-bit DADD, DSUB and DADDI with defined overflow checks; preserve destination atomicity, GPR[0] trap behavior and upper-lane state.
- Decode, lift and AOT-lower VU0 LQC2/SQC2 as checked 128-bit transfers between EE main RAM and the VU0 VF file. VF0 reads as `{0,0,0,1.0f}` and ignores writes; no VU arithmetic or VI register behavior is claimed (ADR 0078).
- Decode, lift and AOT-lower the complete 12-instruction EE conditional trap family using GPR[63:0]; signed and unsigned register comparisons are distinct, all immediate forms sign-extend the 16-bit field before comparison (including TGEIU/TLTIU as unsigned 64-bit comparisons), and true predicates enter Level-1 Trap ExcCode 13 with precise EPC/BD handling.
- Decode, lift and AOT-lower MMI0 PADDW/PSUBW over all four 32-bit lanes and PADDH/PSUBH over all eight 16-bit lanes of GPR[127:0]. Each lane uses modulo-2^N addition/subtraction with no cross-lane carry/borrow; writes to GPR[0] are suppressed.
- Decode, lift and AOT-lower MMI2 PCPYLD, which sets the destination low doubleword from `rt` and the high doubleword from `rs`. The complete 128-bit value is formed before assignment, so a destination aliasing either source preserves both original low lanes; GPR[0] writes are suppressed.
- Decode, lift and AOT-lower MMI3 POR, which ORs both source GPRs over all 128 bits. The complete result is formed before assignment, so a destination aliasing either source observes the original operands; GPR[0] writes are suppressed.
- Decode, lift and AOT-lower MMI0 PEXTLW, which interleaves the low words of both source GPRs as `[rt0, rs0, rt1, rs1]` and ignores both high doublewords. The complete 128-bit result is formed before assignment, so a destination aliasing either source observes the original operands; GPR[0] writes are suppressed.
- Decode, lift and AOT-lower MMI0 PEXTLB, which interleaves the low bytes of both source GPRs as `[rt0, rs0, ..., rt7, rs7]` and ignores both high doublewords. The complete 128-bit result is formed before assignment, so a destination aliasing either source observes the original operands; GPR[0] writes are suppressed (ADR 0059).
- Decode, lift and AOT-lower MMI0 PPACW, which packs the low word of each 64-bit half as `[rt0, rt2, rs0, rs2]` (each result doubleword comes from one source), and MMI3 PCPYUD, which copies the upper doubleword of each source as `result.low = rs.high`, `result.high = rt.high`. The complete 128-bit results are formed before assignment, so a destination aliasing either source observes the original operands; GPR[0] writes are suppressed.
- Decode, lift and AOT-lower MMI2 PEXEW, which exchanges the low word of each 64-bit half as result words `[rt1, rt2, rt3, rt0]`, and MMI2 PROT3W, which rotates the four 32-bit words left by one position as `[rt1, rt2, rt0, rt3]`. Both reserve `rs == 0`, read only `rt`, write only `rd`, and form the complete result before assignment; GPR[0] writes are suppressed.
- Decode, lift and AOT-lower MMI1 PADDUB, which adds 16 unsigned byte lanes with saturation to 255. The complete 128-bit result is formed before assignment; GPR[0] writes are suppressed.
- Decode, lift and AOT-lower MMI2 PAND and PXOR, plus MMI3 POR and PNOR: full 128-bit bitwise operations. Complete results form before assignment; source/destination aliasing is safe; GPR[0] writes are suppressed.
- Discover entry points and STT_FUNC roots, then build a reachability-guided CFG for the currently supported control-transfer subset.
- Recover function-entry candidates in stripped executables with opt-in `--discover`: `JAL` targets backed by executable file bytes and canonical `addiu $sp, $sp, -N` prologues. Candidates are labeled and are not reachability claims; heuristic-only blocks that cannot decode are skipped and reported, while authoritative roots still fail hard.
- Offer a guest `syscall` to a host EE kernel HLE layer that dispatches on the service number in `$v1` (its magnitude, so the ps2sdk "i" wrappers resolve) with arguments in `$a0..$a3` and the result in `$v0`. With the layer disabled — the default — the architectural Level-1 exception is delivered unchanged. With it enabled, a serviced call resumes after the trap, or at the branch target/fallthrough for a delay slot, and a service number without a handler stops as `unhandled_syscall` at the `syscall` with no COP0 context. `SetupThread` (0x3C) returns the documented initial stack pointer, honoring the `0xFFFFFFFF` sentinel and the observed `0x2A0` reserve, and records its arguments; `SetupHeap` (0x3D) records an explicit heap range or the observed `heap_size=-1` stack-end extension and returns the selected end; `CreateThread` (0x20) reads the documented nine-word `ee_thread_t` parameter block through the normal EE memory path and returns an id from a bounded dormant-record table (ids start at 1), refusing zero/misaligned/unmapped function or stack, an overflowing stack range, an unresolvable gp, an out-of-range priority or a full table with the documented `-1` and allocating nothing (ADR 0075); `StartThread` (0x22) moves an existing DORMANT record to the documented READY status, stores the opaque argv pointer and inserts the id into a bounded ready queue ordered by ascending current priority with FIFO among equals, refusing unknown or non-dormant ids with `-1` and changing nothing (ADR 0076); `GetThreadId` (0x2F) reports the boot thread id because only one translated context executes; `ReferThreadStatus` (0x30)/`iReferThreadStatus` writes the documented twelve-word `ee_thread_status_t` for the boot thread (`TH_SELF` or id 1, `THS_RUN`, SetupThread-recorded gp/stack region and `$8` root function, recorded current priority) or a live created record (its CreateThread fields with the DORMANT/READY status the layer assigned), validates the full 48-byte destination before the first store, returns `0`/`-1`, and reports only zero for fields no source records (boot-thread attr/option, wait/wakeup state) (ADR 0120); `ChangeThreadPriority` (0x29) accepts 0..127, updates the boot thread or a created record and recomputes the ready order, changing nothing on refusal (ADR 0076); `GetOsdConfigParam` (0x4B) writes the host-session 32-bit OSD configuration word (initial 0, not persisted) to a validated aligned 4-byte buffer, and `SetOsdConfigParam` (0x4A) stores a validated 4-byte value verbatim without inventing a bit policy; both record refusals and change nothing (ADR 0077); `CreateSema` (0x40) reads the documented 24-byte `ee_sema_t` parameter block and returns a unique id from a 256-object table, refusing inconsistent or unreadable parameters with the documented `-1` and allocating nothing; `DeleteSema` (0x41) frees a slot, `SignalSema` (0x42)/`iSignalSema` (0x43) raise the object's count while below the guest `max_count` and refuse a signal on a full semaphore with the documented `-1`, and `WaitSema` (0x44) consumes a free count or, on a zero count, stops as `semaphore_wait_blocked` because there is no scheduler to make a blocked thread resumable — the modelled SIF RPC bind reply is one producer that raises the count through the shared signal rule (ADR 0104), while every other awaited event still has none — every semaphore service returns the documented `-1` for an invalid id and none fabricates a release; `PollSema` (0x45) and `iPollSema` (0x46) are the documented non-blocking acquire — a positive count is decremented and success returns the passed semaphore id as required by the retail wrapper comparison at `0x00246FA0`, a zero count or an id naming no live object returns `-1`, and the run never stops for a poll, so `semaphore_wait_blocked` stays exclusive to `WaitSema` (ADR 0119) — while `ReferSemaStatus` (0x47/0x48) stays unimplemented (ADR 0101); `SetSyscall` (0x74) validates a 512-slot guest handler registration and publishes the handler pointer into the guest-visible low-RAM syscall table at the ps2sdk-documented base `0x80011F80` (4-byte entries indexed by service number, including the extended slots `0xFC`-`0xFF` and `0x12C` used by client kernel patches), refusing an unwritable table slot; a replaced slot is entered as translated guest code with full context save/restore and `$v0` kept as the result (ADRs 0069 and 0072); `GetEntryAddress` (0x5B) returns the slot address `0x80011F80 + number*4` with 32-bit modular arithmetic (ADR 0073); `FindAddress` (0x83) is an honest host service returning the first matching guest address or `0` = not found (ADR 0068); context dispatch and blocking/scheduling, semaphore waiter lists, the argv rewrite, `root_func`, persistent NVRAM/OSD configuration and every service that depends on it remain unimplemented, as does every other kernel service except the `FlushCache` (0x64) coherent-host no-op (ADRs 0062, 0064, 0066, 0067, 0068, 0069, 0075, 0076 and 0077).
- Preserve control instructions and delay slots as explicit terminators; record direct taken/fallthrough/call/return-continuation edges, the fall-through of a `SYSCALL` as a `syscall_continuation` edge (queued leniently, since it is only code if a host service answers the trap) and unresolved indirect targets. SYSCALL/BREAK in an executed delay slot enter the Level-1 exception vector with EPC pointing at the owning branch and Cause.BD set; branch-likely annulment suppresses the exception when the branch is not taken.
- Check every next guest PC at the shared CFG dispatcher boundary. A word-misaligned instruction fetch raises Level-1 AdEL (ExcCode 4), records the target in BadVAddr and EPC, and clears BD for the completed branch/ERET transfer; aligned targets absent from the translated CFG remain explicit external-control-flow boundaries. Instruction-fetch TLB, bus, and permission faults are not modeled.
- Read executable instructions only from file-backed PT_LOAD bytes; zero-filled BSS is never misinterpreted as code.
- Lift discovered blocks into a CFG-aware typed IR with explicit fallthroughs, branch conditions, direct/indirect jumps, returns, and delay-slot operations.
- Lower the supported CFG subset to a C++20 PC dispatcher; preserve branch/link/delay-slot ordering and stop explicitly at unsupported operations or unmapped control flow.
- Emit each basic block as an independent `block_0xXXXXXXXX` C++ function and dispatch through a sorted table with `std::lower_bound`. `--tu-count N` splits a program into a dispatcher plus `N` independently compilable block parts, and the single-unit default remains available.
- Write a deterministic `<stem>.manifest.json` beside every `recompile-elf` translation: the input path, size and SHA-256, host target, analysis limits and discovery totals, program counts, translation-unit layout, RAM artifact, and an explicit `playable: false` claim. Repeated identical invocations are byte-identical because no timestamps are recorded.
- Generate a deterministic standalone `<stem>.native/` CMake project and host probe with `--native-build`. The same project also builds a shared library with the RG REPS2 ENGINE's versioned exported module descriptor, and the standalone `rg-reps2-engine` runner loads that artifact, owns the session and reports bounded execution in versioned JSON. Its optional raw-ISO media callback is host-owned. CI exercises a generated synthetic shared module through both the loader and runner; no retail-title boot is claimed. The project compiles the dispatcher, every part and the probe against an explicit `REPS2_RUNTIME_INCLUDE`, then registers a CTest that loads the RAM image (when present) and performs one bounded `execute_cfg` call. A CTest integration configures, compiles and runs the generated project end to end.
- Bound analysis with explicit, validated limits and let the developer CLI override them. Defaults are 250,000 basic blocks, 2,000,000 decoded instructions and 500,000 discovered roots; `--max-blocks`, `--max-instructions` and `--max-roots` raise them up to ceilings above the 32 MiB address space. Exhaustion remains fatal even on heuristic roots and speculative syscall continuations; instruction/block capacity is checked before the corresponding count or graph mutation. Limit failures name the flag that raises the bound instead of failing silently (ADR 0085).
- Bound generated execution by a guest-instruction budget, admitting each basic block atomically and preserving its starting PC when the budget is insufficient.
- Decode and lift LB/LBU/LH/LHU/LW/LWU, LD, SB/SH/SW and SD into typed memory IR with width-correct lane updates, natural alignment checks and signed 16-bit offsets.
- Decode and lower LWL/LWR/SWL/SWR and LDL/LDR/SDL/SDR through checked aligned main-RAM accesses and byte-lane merges; preserve unaffected EE GPR lanes and fail explicitly on invalid backing spans.
- Provide caller-owned 32 MiB little-endian EE main RAM with the documented direct, uncached, accelerated, KSEG0 and KSEG1 aliases.
- Perform checked byte/halfword/word/doubleword accesses without unaligned pointer casts; doubleword transfers require 8-byte alignment; report address errors, unmapped ranges, and unimplemented device/MMIO accesses as distinct statuses.
- Route modelled 32-bit device registers through a small MMIO dispatch table in `EeMemory` consulted before main RAM, after direct-mapped KSEG0/KSEG1 address normalization (ADR 0130): the DMAC register file (DPCR `0x1000E000`, D_STAT `0x1000E010`, D_PCR `0x1000E020`, and SIF0 channel-5 CHCR/MADR/QWC/TADR at `0x1000C000`/`0x010`/`0x020`/`0x030`), the Timer 3 mode word `0x10001810`, and the 16-bit Timer 3 compare storage register `0x10001820` (ADR 0131). Each register keeps an explicit known/unknown state and fails closed (`unsupported_memory_access`) until established. `initialize_hle_boot_environment` seeds the kernel-initialized idle DMAC state (all modelled registers known and zero) for a host that opts into the HLE layer; a SIF0 `CHCR` `STR` start is modelled as an immediately completed transfer that publishes the D_STAT SIF0 event and self-clears `STR`. There is no IOP backpressure, timing, other DMAC channel, or SIF DMA chain traversal (ADR 0091).
- Stop SIF0 from guest `syscall` `0x6B` (`sceSifStopDma`): clears only `CHCR5.STR` and preserves the other CHCR fields, matching the documented "Disables SIF0 (IOP -> EE)" entry and PCSX2's completion-time `STR` clear. REPS2's SIF0 starts complete immediately and self-clear `STR`, so an idle channel is unchanged; an unknown channel state fails closed with `unsupported_memory_access`, and `$v0` is not written because the SDK declares the entry `void`. The observed `SifIopReset` prologue calls it after `DisableDmac`/`RemoveDmacHandler` (ADR 0117).
- Model the `SIF_CMD_RESET_CMD` (`0x80000003`) packet the EE sends when it asks the IOP to reboot, and complete the modelled reboot: the request records the packet's `arglen` (bounded to 80) and `mode`, re-arms the resident HLE IOP's RPCINIT handshake so the next `INIT_CMD` is answered again, and marks a boot pending; the EE's next `SMFLAG` (`SIF_REG_SMFLAG` 4) read publishes `SIFINIT | CMDINIT | BOOTEND` (`0x70000`) exactly once, so the retail `SifIopSync` `while (!(SMFLAG & BOOTEND))` loop at `0x0025ED10` completes and the guest resumes into its own `sceSifInitRpc`/`sceSifInitCmd` re-initialisation. A packet shorter than `header + 8` records nothing. The requested `IOPRP270.IMG` replacement image and its IRX set are **never executed** — no IOP RAM, R3000 code, module loader or IOP-side server definition exists, `SIF_SYSREG_SUBADDR` deliberately stays zero rather than inventing an IOP buffer address, and a service only the rebooted IOP would provide still answers nothing (ADR 0118).
- Start the SIF0 DMA channel from guest `syscall` `0x78` (`sceSifSetDChain`): the HLE handler requires a known SIF0 channel and `D_STAT` state — otherwise it fails closed with `unsupported_memory_access` and changes nothing — leaves an already-running channel alone, and otherwise raises `CHCR_STR` so the DMAC owner publishes the SIF0 completion event and self-clears `STR`. It writes no `$v0` because PS2SDK declares the entry `void` (ADR 0092). The EE-side `sceSifSetDma` (`0x77`) service is implemented: it validates the transfer count and guest transfer entries, programs the modeled SIF0 channel registers through the DMAC owner, starts the channel, and returns its transfer ID. ADR 0098 also models selected IOP-side SIFCMD packet effects (`CHANGE_SADDR`, `SET_SREG`, and `INIT_CMD`). These bounded models do not implement a complete IOP, DMA tag traversal/interrupt dispatch, or the full SIF handshake; `SMFLAG` is not seeded, and no CMDINIT completion or game boot is claimed.
- Register a DMAC completion handler from guest `syscall` `0x12` (`AddDmacHandler`): one bounded record per channel (0..9) holding the handler address, chain pointer and registering PC, with an HLE-local id equal to the channel index. A null, misaligned or out-of-RAM handler, an out-of-range channel, a non-zero `next` and a duplicate registration are refused with `-1` and create nothing. No interrupt is delivered and no mask is touched, so a registered handler is never invoked (ADR 0095).
- Remove a DMAC completion handler from guest `syscall` `0x13` (`RemoveDmacHandler`): removes the channel's record only when the channel is valid and its id equals the HLE-local handle; the removed handler address and channel are recorded, and the handler count drops. An unregistered channel, a wrong id or an out-of-range channel changes nothing and returns the layer's `-1`; `$v0` is left unwritten on success because the kernel's return value is not observable. This completes the SDK `sceSifExitCmd` teardown `DisableDmac(5); RemoveDmacHandler(5, id)` observed at `0x25C3B0`. `AddDmacHandler2` (the `0x12` alias) and the handler dispatch chain remain unimplemented (ADR 0116).
- Enable a DMAC channel interrupt from guest `syscall` `0x16` (`EnableDmac`): sets the channel's `D_STAT` interrupt-mask bit (bits 16..25, write-one-to-toggle) only when it is currently clear, so a second call never toggles an enabled channel off and reports `already_enabled`. An out-of-range channel is refused with `-1`; an unknown DMAC register state stops with `unsupported_memory_access`; `$v0` is left untouched on success because the kernel's return contract is not observable. No interrupt is delivered, so the mask bit has no further effect (ADR 0096).
- Disable a DMAC channel interrupt from guest `syscall` `0x17` (`_DisableDmac`): the symmetric operation clears the channel's `D_STAT` mask bit only when it is set, leaves an already-disabled channel untouched and reports `already_disabled`, refuses a channel above 9 with `-1`, leaves `$v0` untouched on success and fails closed on an unknown register state. It does not cancel a transfer or deliver an interrupt. The observed post-CdInit path calls it with channel 5; the probe reports `disable_dmac`, `disable_dmac_channel` and `disable_dmac_outcome` (ADR 0115).
- Read SIF registers from guest `syscall` `0x7a` (`sceSifGetReg`): the four documented hardware registers (1..4, EE `0x1000F200`..`0x1000F230`) and the three kernel software registers (`0x80000000`+0..2) are served from an HLE-owned register file whose values initially start at zero, because no IOP-side SIF command system is installed before the HLE boot environment initializes it. Each read returns its value in `$v0` and is recorded; an undocumented register number stops as `unhandled_syscall` instead of answering with an invented value (ADR 0097). Following a well-formed `SIF_CMD_RESET_CMD`, the modelled resident HLE IOP completes its restart on the next SMFLAG read by publishing `SIFINIT | CMDINIT | BOOTEND`, re-arms the RPCINIT reply for the next EE `INIT_CMD`, and leaves the unmodelled IOP `SUBADDR` at zero (ADR 0118).
- Write SIF registers from guest `syscall` `0x79` (`sceSifSetReg`): writes the addressed hardware (1..4) or software (`0x80000000`+0..2) register in the same HLE-owned file and records the write; an undocumented register number stops as `unhandled_syscall`. This shares the register file with `sceSifGetReg` (ADR 0098).
- Program a SIF DMA transfer from guest `syscall` `0x77` (`sceSifSetDma`): validates `count` (1..2), reads the `SifDmaTransfer_t` array, programs the SIF0 channel-5 MADR/QWC/TADR/CHCR registers through the DMAC owner, starts the channel with `CHCR_STR`, and returns the 1-based transfer id. The DMAC owner still models a start as immediately complete; no interrupt is delivered (ADR 0098).
- Model the IOP-side SIFCMD system commands a submitted command packet carries: `CHANGE_SADDR` records the IOP's send-to-EE destination, `SET_SREG` writes a bounded 32-entry software-register bank, and `INIT_CMD` with `opt == 0` records the EE receive buffer and raises `MSFLAG` CMDINIT (with `opt != 0` leaving them untouched). The packet is parsed from the EE source address of the `SIF_DMA_ERT` transfer entry (ADR 0098).
- Model the resident IOP `SIFCMD` module's startup as device state: an absent/resident lifecycle whose idempotent startup publishes the documented `SMFLAG` `SIF_STAT_CMDINIT` bit through the shared SIF register file, matching the pinned PS2SDK IOP `sifcmd` `_start` sequence. The boot environment runs it because the replaced EE kernel loads the IOP replacement image. The device publishes no IOP `SADDR` value (REPS2 has no IOP RAM, so inventing a buffer address is refused) and never writes the EE-owned `MSFLAG`. SIF register-number/status-flag constants live beside the device state, and the generated probe reports `sif_iop`, `sif_smflag`, `sif_msflag`, `sif_hw_subaddr`, `sif_get_regs`, `sif_set_regs`, `sif_set_dma` and `sif_cmd_*`. The real-title trace now advances from the `SMFLAG` wait loop to the SIF RPC wait loop at `0x0025C928`; SIF1/RPC dispatch and DMAC completion interrupts remain unimplemented, so no boot stage is claimed (ADR 0099).
- Model the resident IOP `SIFRPC` module's answer to an EE RPC bind: with no IOP module loaded, no `sceSifRegisterRpc` has populated a server queue, so `SIF_CMD_RPC_BIND` is answered with the documented `SIF_CMD_RPC_END` no-server reply (`sd` = buf = cbuf = NULL) for the request's `cd`/`pkt_addr`. The reply is written into the guest-published EE receive buffer, publishes the SIF0 `D_STAT` event, and is dispatched by `process_ee_sif_command`, which performs the EE-side `_request_end` effects: write the client's `server`/`buf`/`cbuf`, raise the client semaphore through the shared signal rule, and free the request packet. A bind therefore fails exactly as it would on an IOP without that module, and the title continues on its own error path. Delivery fails closed with no published or unwritable receive buffer. The probe reports `sif_rpc_bind`, `sif_rpc_bind_sid`, `sif_rpc_bind_sema` and `sif_rpc_bind_signalled`.
- Model a bounded IOP SIFRPC server table and serve `CdInit` (ADR 0114): `initialize_hle_boot_environment` registers only servers the runtime implements, each as `{sid, queue, handler}`; lookup follows `search_svdata` order (lowest queue, then registration). A registered bind replies with the sid as the opaque `sd` token — the observed EE only zero-tests `cd->server` and copies it into call packets — while `buf`/`cbuf` stay zero because no IOP buffer address is modelled. `SIF_CMD_RPC_CALL` is decoded from the call packet plus the payload entry that `sceSifSendCmd` sends before it; the handler writes its reply directly into the caller's EE buffer, and a `SIF_CMD_RPC_END` naming `cid = SIF_CMD_RPC_CALL` releases the caller's semaphore and frees the request. CdInit (`0x80000592`, function 0) answers `{1, 0, 0, 0}` (driver accepted initialization; versions are the SDK's "not reported" zero, no disc status implied). The CDVDFSV S-command server (`0x80000593`, ADR 0121) is also registered so the title's bind loop completes. Its handler models only `CD_SCMD_MMODE` (0x22, ADR 0122): a 4-byte request records the media word (`cdvd_mmode`, mirroring cdvdman's `g_cdvdman_mmode`) and answers `m_retres = 1` — the exact IOP behavior — releasing the caller's semaphore via `SIF_CMD_RPC_END`. Every other S-command number, or a malformed MMODE request, is refused so the caller stays blocked while the dispatch records the S-command number (the RPC function number, per PS2SDK `scmd.c`) and the call's first payload word for the probe. An unregistered token, a refused function number, an absent payload or `rmode == 0` produces no reply, so the caller stays blocked. The probe reports `sif_rpc_call*`, `rpc_call_req`, `scmd_calls`/`scmd_replies`/`scmd_number`/`scmd_media`/`scmd_retres`/`scmd_replied`/`cdvd_mmode` and `sif_rpc_bind_server`/`sif_rpc_bind_had`. Guest `end_function` callbacks, the remaining S-command bodies, DiskReady/SearchFile/read servers, SIF1 traffic and DMAC interrupt delivery remain unimplemented.
- Model the IOP-to-EE SIF0 RPCINIT reply: on the EE's `INIT_CMD` (`opt == 0`) handshake the resident IOP replies with `SIF_CMD_SET_SREG(index = SIF_SREG_RPCINIT, value = 1)`. REPS2 writes the documented 24-byte packet into the guest-published EE receive buffer, publishes the SIF0 `D_STAT` event (`EeDmacState::publish_sif0_event`), and dispatches it through the EE-side SIFCMD receive handler `process_ee_sif_command`, which performs the documented `cmd_data->sregs[index] = value` write, locating `sregs` through the guest-published `SIF_SYSREG_MAINADDR` (offset `0x1C`, confirmed in the retail image at `0x0025C0D8`/`0x0025C1C0`). No hardcoded address or value is written and no CPU interrupt is delivered: the EE-side system handler is HLE, not guest code. The reply runs once per boot and fails closed when the receive buffer is unwritable, `cmd_data` is unpublished, `sregs` is null, or the index is out of range; the probe reports `sif_ee_inbound`, `sif_ee_inbound_cid`, `sif_ee_sreg0`, `sif_rpcinit_sent` and `sif_ee_sif0_event`. This releases the SDK RPC wait loop at `0x0025C928` (ADR 0100). The EE CPU interrupt path, INTC, and RPC dispatch beyond `SET_SREG` remain unimplemented.
